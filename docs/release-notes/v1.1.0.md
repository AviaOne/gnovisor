GnoVisor v1.1.0 adds a Docker mode and makes the vote the only trigger of an
update.

## Changes

- **No update without a vote.** GnoVisor now stops and updates the node only
  at a halt voted on the chain by GovDAO. A halt height the ledger, or a
  version added by hand, announces with no vote behind it, or one a later
  vote moved or cancelled, changes nothing: the chain goes on, and the node
  keeps running on its version. A halt the ledger records as past (with its
  `halt_time`) is still crossed while syncing from genesis.
- **Docker mode.** With `runtime = "docker"` in `gnovisor.toml`, or
  `gnovisor init -runtime docker`, GnoVisor runs the node in a container from
  the official `gnoland` image of each version, pinned by digest, and at a
  voted halt switches it to the image of the new version. Everything else is
  as for a node run from a binary: the ledger, the preparation ahead of the
  halt, the backup, the commands. A version added by hand is given as an
  image (`gnovisor add-upgrade -image <repository@sha256:...>`).

## Upgrading from v1.0.0

Replace the binary as described in the README, "Updating GnoVisor". Nothing
changes in `gnovisor.toml` for a node run from a binary.
