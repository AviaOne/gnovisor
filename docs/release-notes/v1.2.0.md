GnoVisor v1.2.0 takes the version of an update from the vote, so that the
update no longer waits for the ledger.

## Changes

- **The vote names the version.** Since October 2026 gno.land writes the
  ledger entry of an update only once the chain runs it, after the halt.
  Every halt proposal sets the version released as `halt_min_version`:
  GnoVisor now prepares that version ahead of the halt, from its official
  image read by tag and its `GNOROOT` cloned at the tag, and switches at the
  halt. The ledger is still read: for past halts while syncing, and to
  compare the image digest and the commit once the entry is written.
- **A version added by hand always wins.** At its halt, a version added with
  `gnovisor add-upgrade` is run, whatever the vote or the ledger names; a
  different ledger version is logged.
- **A chain slow to resume no longer stops the node.** After a halt, when no
  block comes within `restart_timeout`, GnoVisor logs it and lets the new
  version run: it catches up as soon as the chain resumes.
- **The ledger written after the halt is followed.** If it names, for the
  blocks after the halt, a newer version than the one in service, GnoVisor
  switches to it.
- `gnovisor status` and `gnovisor prepare` take the version in the same
  order: added by hand, the ledger, the vote.

## Upgrading from v1.1.0

Replace the binary as described in the README, "Updating GnoVisor". Nothing
changes in `gnovisor.toml`.
