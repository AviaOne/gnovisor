First release of GnoVisor, the upgrade supervisor for gno.land nodes.

GnoVisor starts your `gnoland` node, watches the chain for a coordinated halt
programmed by GovDAO, prepares the new version ahead of time, and at the halt
backs the node up, switches it to the new version and starts it again, with no
one at the keyboard. It serves gno.land only and has no dependency outside the
Go standard library.

## What it does

- **Coordinated halts.** Reads the halt height from the node's RPC, finds the
  version in the gno.land upgrade ledger, takes its binary from the official
  image the ledger names, and clones its `GNOROOT` at the version's tag with
  the commit checked against the ledger. At the halt height it reads the
  ledger again and switches at once: the halt block is committed and the node
  will produce nothing more.
- **Runs on every Linux.** The binaries attached to the gno.land releases are
  built with CGO and need glibc 2.38 or later; they do not start on Ubuntu
  22.04. The gnoland image `ghcr.io/gnolang/gno/gnoland:<version>` is built
  with `CGO_ENABLED=0`: GnoVisor downloads it over HTTPS, without Docker,
  checks it against its digests, and extracts its static binary. The node
  must use the default database backend (`pebbledb`) or `goleveldb`.
- **Never the old binary after a halt.** When a halt is reached and its
  version is not ready, the node stays stopped, the halt is recorded on disk,
  and GnoVisor reads the ledger again every minute until the version appears.
  A restart of GnoVisor or of the machine never starts the old binary in the
  meantime.
- **Sync from genesis.** A node replaying the chain stops at every past halt;
  GnoVisor restarts it on the version the ledger names for the blocks that
  follow.
- **Rolling releases.** Patches the ledger publishes with no halt are installed
  inside a daily UTC window each operator sets, so that validators do not all
  restart together.
- **Versions added by hand.** `gnovisor add-upgrade` takes a binary and its
  `GNOROOT` received outside the ledger, such as a security fix handed to
  validators privately, for a halt or as a rolling patch.
- **Backups.** The node directory is copied before every switch, never with
  `secrets/`, and a backup is never deleted or overwritten.
- **A failed version is followed by its fix.** When the new version refuses
  to start or produces no block after a halt (an app hash mismatch, for
  example), the node stays stopped and GnoVisor reads the ledger every
  minute: as soon as gno.land names another version for that halt, it is
  prepared and the switch is made again.
- **Failures stop, they do not guess.** A failed backup, or the ledger and a
  version added by hand disagreeing on the same halt: the node is left
  stopped, the error is logged, and GnoVisor waits for an operator.

## Installing

See the installation steps in the README. `gnovisor init -version <vX.Y.Z>`
takes the version your node runs today by itself, binary and `GNOROOT`, and
GnoVisor then replaces your current node service. No Go and no Docker are
needed on the server.
